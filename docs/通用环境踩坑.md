## 1. C++ 头文件包含路径错误（无法打开包括文件）

### 现象
编译时报错 `无法打开包括文件: "xxx.h": No such file or directory`，但文件确实存在于项目目录中。

### 排查与原因
- `#include "..."` 的相对路径是相对于**当前正在编译的 .cpp 文件所在目录**解析的，不是相对于项目根目录或 src/ 目录
- 例如 `src/core/scanner.cpp` 中写 `#include "model/file_info.h"`，编译器会去找 `src/core/model/file_info.h`，自然找不到
- 项目按模块分子目录后，如果 include 路径仍写相对于 src/ 的路径，就会批量报错

### 解决方案
两种方式任选其一：
1. **设置附加包含目录（推荐）**：在 `.vcxproj` 的每个配置 `<ClCompile>` 中加 `<AdditionalIncludeDirectories>src;%(AdditionalIncludeDirectories)</AdditionalIncludeDirectories>`，之后所有 include 统一写相对于 src/ 的路径
2. **逐个文件改相对路径**：每个文件自己算 `../`，如 `src/core/scanner.cpp` 里写 `#include "../model/file_info.h"`

### 经验总结
- C++ 项目按模块分目录后，第一时间设置附加包含目录，避免后续每个文件都算相对路径
- 附加包含目录只对头文件搜索有效，`.cpp` 文件仍需在 `.vcxproj` 中显式声明 `<ClCompile>` 才能参与编译

## 2. 文件行尾不一致（LF vs CRLF）

### 现象
Visual Studio 打开文件时弹出"不一致的行尾"对话框，提示文件中混合了 LF 和 CRLF 行尾，询问是否标准化。

### 排查与原因
- Windows 标准行尾是 CRLF（`\r\n`），Linux/Unix 是 LF（`\n`）
- 通过脚本、外部工具或跨平台编辑器创建的文件可能使用 LF 行尾
- 文件中如果同时存在两种行尾，VS 会检测到并提示

### 解决方案
1. 单个文件：在弹出的对话框中点"是"，VS 自动统一为 CRLF
2. 批量处理：用 PowerShell 脚本遍历所有源文件，先把 CRLF 转 LF，再统一转回 CRLF
3. 预防：在 `.gitattributes` 中设置 `* text=auto eol=crlf`，让 Git 自动处理行尾

### 经验总结
- Windows 下的 C++ 项目统一用 CRLF，避免编辑器和编译器警告
- 用脚本批量创建文件后，检查行尾是否一致

## 3. 源码编码与中文乱码（UTF-8 BOM）

### 现象
- 代码中文字符串在控制台输出乱码
- 或编译时报错 `C2001: 常量中有换行符`、`C2143: 语法错误: 缺少";"`
- 同一项目中部分文件中文正常，部分文件乱码

### 排查与原因
- Windows 下 Visual Studio 默认用系统代码页（GBK/GB2312）解读源码文件
- 如果源码文件保存为 UTF-8（无 BOM），VS 会按 GBK 解读，中文就乱码
- 如果文件编码不统一（部分 GBK、部分 UTF-8），就会出现部分正常部分乱码
- 某些看似语法错误的编译报错，也可能由编码问题间接导致（中文字符被错误解析后影响语法）

### 解决方案
1. 统一所有源码文件为 **UTF-8 with BOM** 编码（VS 能正确识别 BOM 并按 UTF-8 解读）
2. 或在 `.vcxproj` 中加编译选项 `/utf-8`，强制编译器按 UTF-8 解读所有源文件
3. 控制台输出中文时，设置 `SetConsoleOutputCP(CP_UTF8)` 或 `system("chcp 65001")`

### 经验总结
- 中文 C++ 项目从一开始就统一编码（UTF-8 with BOM 或 /utf-8 编译选项），不要混用
- 出现莫名其妙的语法错误时，先检查文件编码

## 4. .gitignore 误配置导致所有文件被忽略

### 现象
- `git status` 显示所有文件都被忽略，`git add .` 不添加任何文件
- 或新创建的文件在 Git 中不可见

### 排查与原因
- `.gitignore` 中误写了 `* text=auto`（这本来是 `.gitattributes` 的语法）
- `.gitignore` 中 `*` 表示忽略所有文件，导致整个仓库的文件都被忽略
- `.gitignore` 和 `.gitattributes` 的语法不同，不能混用

### 解决方案
1. 从 `.gitignore` 中删除 `* text=auto` 这类 `.gitattributes` 语法
2. 行尾管理应该写在 `.gitattributes` 中，如 `* text=auto eol=crlf`
3. 修改后用 `git check-ignore -v <文件名>` 验证文件是否还被忽略

### 经验总结
- `.gitignore` 只写忽略规则（文件路径和通配符），属性设置写在 `.gitattributes`
- 修改 `.gitignore` 后用 `git status` 验证，确认没有误忽略
